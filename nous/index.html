Nous's commitment to open, broadly accessible intelligence is why this work matters to me. That makes Nous the rare place where the larger Faber thesis can receive a serious positive or negative result.

Proposed work

Verify real work. Then test whether it teaches.

Faber binds a task contract, exact attempt and environment, authorized verifier evidence, outcome, cost, and data rights into a portable episode. The original bounty market was one mechanism for generating real work; Faber Proof is the current experiment in earning the outcome label rather than accepting a model's self-report. The proposed Hermes pilot tests the complete loop without assuming in advance that verification makes the resulting episode more useful.

This is an open application to pursue Faber with the Nous team, not an application to a listed opening. Faber is pre-existing public work. I am asking whether Nous would hire me to investigate, test, and—if the evidence supports it—build it with the team. It is not a renamed version of an existing job.

Days 1–14

Map before building

Build nothing new. Map how one bounded public Hermes task class is attempted, judged, retained, and reused today. Freeze the strongest existing baseline and precommit to security, differentiation, maintenance-burden, and downstream-value kill criteria.

Days 15–60

Earn the outcome label

Re-verify Faber Proof, then run it in shadow mode around real attempts. Bind the task, attempt, environment, executed evidence, result, cost, and latency. Compare label quality, reproducibility, false accepts, false blocks, referrals, and policy burden against the matched baseline.

Days 61–90

Test the learning claim

Only if the labels are better at acceptable cost, test whether the outcome-bound episodes improve one held-out decision—for example attempt, worker, or strategy selection—over a matched baseline. Finish with a continue, narrow, open-source, or stop decision.

01

Nous hackathon agent-bounty prototype

The origin and larger thesis of Faber.

Faber began as an agent-native bounty market submitted to a Nous/NVIDIA/Stripe hackathon. It reserved tasks, evaluated exact commits against protected verifier targets, produced commit-bound acceptance receipts, and made payout and reconciliation idempotent.

The market was one mechanism for generating real tasks. The larger idea was to bind task, attempt, evidence, and outcome so completed work could become a trustworthy learning episode. A member of the Nous team responded especially strongly to that concept.

Public hackathon prototype · Earlier and broader than Faber Proof.

02

Faber Proof

The label-integrity experiment for agent-written patches.

I designed and built, using Codex as an implementation agent, a local Python alpha in which model-generated proof plans are advisory. Repository-approved capabilities execute bounded checks; evidence is bound to the exact task, patch, policy, and environment; deterministic logic returns PASS, BLOCK, or HUMAN_REVIEW.

In a constructed scheduler case, ordinary tests accept both a flawed patch and its repair. Faber blocks the flaw with a concrete boundary-condition counterexample and accepts the repair.

Current local checkpoint: 725 passing tests, one guarded live-provider test skipped, and a 49-case deterministic adversarial regression campaign. The audit remains non-green: four P0 findings have remediation candidates and targeted regression tests, but await fresh independent re-verification. This is development evidence, not production testing or a claim of general program correctness.

03

Motoko

A security- and privacy-focused local assistant harness.

Motoko is a public, standard-library Python terminal assistant built around local llama.cpp endpoints. It combines source-visible context, hybrid retrieval and reranking, named model routes, procedural skills, and durable checkpointed jobs. Private content remains in realm-local state; source documents stay behind explicit allowlists and are read-only by default.

Its engineering rule is that model output is planning data, not authority. Unknown effects fail closed; scripts remain inert until their code and effect contract are fingerprint-approved; project writes require an allowlisted path, .motokoignore enforcement, exact-session confirmation, hash checks, atomic writes, and an inspectable ledger. Long jobs stay bounded, resumable, and off the render and input path.

Public work in progress · Nix-packaged · stdlib runtime · 329 defined regression cases, 15 evaluation checks, and six PTY checks. A fresh full validation run and external security/performance review are still needed; approved scripts are policy-confined but not OS-sandboxed. Public source

04

Hermes workflow case

Reconciliation before confidence.

Using Hermes, I built and validated a public-source ingestion workflow, then treated reconciliation as an evaluation problem rather than trusting the first successful run. It used twscrape for acquisition and Nitter as an independent cross-check, preserved upstream IDs and provenance, rejected contextual parents, committed per account, and advanced checkpoints only after successful transactions.

In the first 72-hour validation window, two result pages yielded 43 parsed source records and 30 canonical target-author activities. Nitter’s 24 IDs were an exact 24/30 subset after repost-wrapper canonicalization; an idempotence rerun added zero records. I also reversed my initial “zero results” diagnosis after finding that conversation modules were not strictly ordered.

Local work sample · Code and run artifacts available for technical review.
